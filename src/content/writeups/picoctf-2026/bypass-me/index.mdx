## Challenge Description

> Your task is to analyze and exploit a password-protected binary called bypassme.bin and binary performs a multi-step verification process before granting access.

---

## Recon / Initial Analysis

This is a classic reverse engineering challenge where a binary performs multiple password verification steps. The goal is to either:

1. **Extract the password** by reverse engineering the verification logic, or
2. **Bypass the checks entirely** by patching the binary (changing conditional jumps)

The "multi-step verification" suggests the binary has several sequential checks, such as:
- String length verification
- Character-by-character comparison
- Hash/checksum validation
- Anti-debugging checks
- Obfuscated comparisons

Initial reconnaissance:

```bash
file bypassme.bin
checksec --file=bypassme.bin
strings bypassme.bin | grep -i "pass\|flag\|correct\|wrong\|step\|verify"
```

---

## Vulnerability / Observation

Each verification step likely compares parts of the input against expected values. By analyzing the comparison instructions in the disassembly, we can extract what values are expected or simply patch the binary to skip the checks.

Key techniques that apply here:
- **Static analysis**: Decompile with Ghidra/IDA to understand the verification logic
- **Dynamic analysis**: Use GDB to step through checks and observe comparisons
- **Binary patching**: Modify conditional jumps (e.g., `jne` -> `je` or `jmp`) to bypass checks
- **ltrace/strace**: Intercept library calls like `strcmp`, `strncmp`, `memcmp`

If `strcmp`/`strncmp` is used, the expected password will surface directly in an `ltrace` trace; otherwise the comparison instructions in `main()` reveal the expected values.

def try_ltrace(binary_path):

    print("[*] Method 1: ltrace interception")

        proc = subprocess.run(
            ["ltrace", "-s", "256", "-e", "strcmp+strncmp+memcmp+strcasecmp", binary_path],
            input=test_input,
            capture_output=True,
            text=True,
            timeout=10,

        patterns = [
            r'str(?:n?)cmp\(".*?",\s*"([^"]+)"',
            r'str(?:n?)cmp\("([^"]+)",\s*".*?"',
            r'memcmp\(.*?,\s*"([^"]+)"',
            r'strcasecmp\(".*?",\s*"([^"]+)"',

## Key Takeaways

- A password-protected binary with sequential checks can be defeated either by **extracting** the expected values or by **bypassing** the conditional logic entirely.
- `ltrace` is the fastest win when comparisons use libc functions (`strcmp`/`strncmp`/`memcmp`) — the expected password appears directly as a function argument.
- Conditional-jump patching (`jne` 0x75 ↔ `je` 0x74, or long-form `0F 85` ↔ `0F 84`) inverts or skips a check without ever knowing the password.
- GDB can dump comparison arguments at runtime (`x/s $rdi` / `x/s $rsi`) or force a branch by flipping the zero flag in `$eflags`.
- `angr` symbolic execution is a strong fallback: explore toward "Correct"/"picoCTF" strings while avoiding "Wrong"/"Invalid".
